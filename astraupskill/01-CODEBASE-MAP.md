# Follow identity, domain values, and persisted state

[The application factory](../backend/src/app.ts) builds the Express middleware and routes without opening a server. [The entry point](../backend/src/index.ts) reads environment configuration, listens on loopback, and closes HTTP/Prisma resources on shutdown. Tests can instantiate the same application and drive real HTTP behavior without depending on an unmanaged process.

[Authentication](../backend/src/middleware/auth.ts) verifies token algorithm, issuer, audience, subject, and expiry, then reads the user's current role and employee status from PostgreSQL. A request gets a server-derived actor containing user ID, role, and employee ID. The caller cannot choose the approver or target employee through a leave-create body. Accounts without a password cannot sign in; creating an employee record is separate from provisioning an account invitation.

[Validation](../backend/src/lib/validation.ts) defines editable shapes, date rules, exact statuses, version bounds, and query limits. [Employee services](../backend/src/services/employeeService.ts) enforce HR-only mutations before calling [the employee repository](../backend/src/repositories/employeeRepository.ts) or [department repository](../backend/src/repositories/departmentRepository.ts). Employee creation and updates treat User identity fields and Employee profile fields as one aggregate, with a shared version and transactional audit.

[Leave services](../backend/src/services/leaveService.ts) validate requests and dispatch to [the leave repository](../backend/src/repositories/leaveRepository.ts). That repository applies current ownership and manager scope, locks the relevant employee row, checks overlap and state, performs a conditional versioned mutation, and inserts audit metadata in one transaction. [Shared scope helpers](../backend/src/repositories/scope.ts) define access predicates, selected public fields, DTO conversion, row locks, and audit insertion. Password hashes are not part of the returned employee selection.

[The Prisma schema](../backend/prisma/schema.prisma) repairs the original User/Employee, manager, leave-decider, and reviewer relationships. The fresh migration adds inclusive-date exclusion and other database constraints. Review remains a schema extension point; there is no review-management UI in this implementation.

On the frontend, [App](../frontend/src/App.tsx) owns the in-memory session and section selection. [The API client](../frontend/src/api/client.ts) handles authenticated requests, errors, timeouts, cancellation, and draft downloads. [The editor hook](../frontend/src/hooks/useWorkspace.ts) coordinates busy state, retained errors, navigation guards, and resource cleanup. Employee, department, and leave pages hold their own accepted baseline and editable draft. Query refreshes do not silently replace those drafts.

Draw a source map with two arrows for every operation: acceptance and rejection. An invalid date fails before a write. A wrong actor fails authorization. A stale version preserves the draft. An audit failure rolls back the entity mutation. A timeout may leave acceptance uncertain. Label each arrow with a test and explain the resulting user action. That map is more useful than memorizing a list of framework names.
